i will start if God wills a full rewrite of the plugin to remove pydantic dependency, there is at least 3 alternatives as discussed here https://github.com/CudaText-addons/cuda_lsp/issues/217
- dataclasses
- attrs cattrs
- attrs cattrs + lsprotocol

Which method of 3 is best?
lsp servers maintainers will always update their servers to follow the latest lsp protocol (which may/will change in the future), so we need to use lsprotocol to minimise the plugin maintenace in the future because it s maintained by microsoft which maintain also the lsp protocol, so both the python addon and lsp protocol will be always in sync if God wills by microsoft

and because lsprotocol use attrs/cattrs so no need to use the builtin dataclasses, because we will be using attrs indirectly, and because attrs offer more powerfull functions then lets just use it too

and even if the future python versions become incompatible and broken with the old attrs/cattrs for python 3.8, we can include newer versions of attrs inside our lsp plugin because it s pure python and small (in the main page they say: attrs is a Python-only package https://www.attrs.org/en/stable/index.html so i suppose it will continue like that in the future)

but if they change that and become like pydantic (using rust or c/c++), then we have to return to dataclasses and remove lsprotocol python package and just write manually the structures and classes, but this will need more effort to maintain

so the answer is: attrs+cattrs+lsprotocol
